# 飞书每日形象图

## 交付与默认值

为用户指定账号准备目标日期的一组8张独立9:16照片，人物身份一致，动作、服饰、环境、镜头距离有变化；保存本地文件，并在用户要求同步时写入同账号、同使用日期的一行“人物形象”附件。

- “明天”按用户所在时区的当前日期加一天，开始时说清绝对日期。不要用技能建立日期或历史对话日期计算。
- 默认8张；已有目标日图片时先确认是补齐还是新增一组，不重复生成或覆盖。
- 用户重视速度，普通手机照片画质即可，无需超清和反复精修；降低提示词细节要求不等于工具具有可设置的低画质参数，不承诺固定耗时。
- 只处理本次指定账号，账号范围来自用户提供的配置，不因示例擅自扩展。

首次使用此技能时，向用户简短说明正在使用。涉及飞书操作先读取可用的 `lark-base` 技能；遇到授权问题使用 `lark-shared`。生成图片先读取 `imagegen` 技能，使用内置生图工具。无可用依赖时说明具体阻碍，保留可继续的结果；不要自行转用付费API、建立新应用或修改全局安装。

## 读取参考与定位

1. 优先使用用户本次给的飞书链接或账号配置；已有本机 `references/accounts.local.md` 时可读取。配置格式见 [references/profile-template.md](references/profile-template.md)。资源ID只作入口，必须核验当前表名、字段与记录。
2. 标题查找走 `base +title-resolve`，链接走 `+url-resolve`。精确标题未匹配时可尝试短关键词；多候选按真实标题、所有者确认，不猜资源。
3. 读取账号表字段、记录和附件，确认“使用日期”“人物形象”以及已有目标日行。小表可完整读取；`has_more` 为真必须继续分页才能声称不存在目标日期。
4. 优先选用户指定的参考行；其次选目标日期之前最近一个有图的使用日期。不要因空行、编码或创建时间猜素材使用日期。日期缺失或同日期有多个候选时用当前上下文消歧，仍不明确才询问。
5. 下载参考图片到当前工作区 `work/` 子目录。图片必须通过 `view_image` 实际查看后才作为本地参考传入图片工具。无需下载音频或改动音频表。

## 样图与生成

读取 [references/prompts.md](references/prompts.md)，围绕参考人物形成8种组合。人物是同一个人，不能把“8张不同形象图”解释成8个不同人。

- 锁定脸型、五官、年龄、发型、胡须、体型和气质。默认允许变化符合该账号人物设定的服饰、坐站姿态、小手势、室内外背景和近中远景；原图不是必须保持的像素模板。
- 每个账号独立查看参考，不能套用其他账号的脸或老者茶室范例；特征性头饰、红脸妆、铠甲等应保留，服饰调整在角色设定内进行。
- 按人物设定选择环境风格：关羽等神将、神祇或明确用于祈福祝福的神话角色，默认采用庄严祥和的金色殿堂、柔和圆形金色光环和克制的暖金辉光；普通人物保持自然生活摄影场景，不自动添加光环或神化效果。仅有古装、长须或中式服装不代表神祇；无法判断时尊重参考设定或先出样图。用户明确指定的风格优先。
- 神将祝福图保留角色身份，表情威严而平和、正对镜头，动作稳重适合口播；金殿背景适度虚化，光环位于头部后方外侧，不穿过脸、头饰或身体。避免金光遮脸、爆炸特效及满屏粒子。批量变化殿堂布置、镜头、手势和光线，不必每张同时堆满所有元素。
- 若用户要求衣服或动作小改，则收紧对应维度；后续用户放宽范围时以最新指令为准。保持背景适度虚化，脸和手自然清楚。
- 新人物或未确认的新风格：先生成2～3张方向不同的样图并展示，等待反馈，再生成剩余数量。用户明确要求直接做全套或同账号风格已经确认时，无需每次重新请求确认。
- 若用户说“先做两三张”，立即停止新增批量任务；已提交请求可收集保存，但不得声称尚未提交或静默上传全部。
- 每张独立调用内置生图工具。独立请求可用 `Promise.allSettled` 同时提交；多账号时限制在当前可承受的一组并发。并行请求不需要额外Agent，不承诺启动Agent会缩短服务端生图耗时。
- 将每张的提示词、参考文件路径、输出路径、状态保存到工作区清单，完成一张即更新，便于失败后续接。不要打印返回对象中的base64；只返回编号和小段路径信息。需要直接展示工具结果时使用 `generatedImage(result)`。
- 等待期间及时更新完成数量。工具返回的 `output_hint` 可提供实际本地路径；复制成项目交付文件，例如 `账号1_2026-11-06_01.png`。不猜输出目录，不把整批画成拼图再拆分。

## 检查与同步

1. 实际查看成图，检查同人物、竖版、手和面部自然、无文字水印、各张有合理差别。只重试失败或明显不合格的编号；不要为普通画质整批重做。不能保证平台一定不判定同质化。
2. 用户只要样图时到此停止，展示2～3张并等待；用户已要求生成后同步时，合格结果即可继续，不重复问权限。
3. 同步前重新查目标日期行。已有一行就使用该行；没有则新建一行并填“使用日期”。若有多个匹配行或已有附件与本地清单不一致，先停止写入并消歧。不要随意占用编码2之类空行；用户已经指定的目标行除外。
4. 若缺“使用日期”，按lark-base字段规范创建 `datetime` 日期字段，显示 `yyyy-MM-dd`；写值用 `YYYY-MM-DD 00:00:00`，以返回时区核验。字段名称存在但类型不对时，不擅自转换或覆盖。
5. 普通记录接口只写日期与备注等存储值。图片通过 `+record-upload-attachment` 上传，可在一次请求中重复8个 `--file`，追加到同一人物形象单元格；不把file token作为普通附件CellValue写入。
6. 重试前读回附件，按文件名和清单判断已上传编号，只上传缺少部分。上传超时不代表失败，不盲目重传。失败时保留本地图片，说明剩余哪些未同步。
7. 成功后确认目标行日期正确、图片数和本次上传数正确，记录表ID、record ID和文件token。若命令返回不足才额外读回核验。
8. 不删除或覆盖历史图片，不重排其他账号，不清理记录或字段，不改音频表。本技能不创建定时任务；若用户另行要求每日自动运行，按可用自动化工具单独配置。

## 最终回复

简短告知账号、绝对使用日期、生成/同步张数、飞书表格链接及本地交付位置；未完成同步时明确说出。用户尚未认可样图则只展示样图，不声称全套完成。提示词与生成记录随交付保存，使用内置生图工具的事实记入清单。
