# 公众号短文创作与飞书入库

交付单位为一条完整草稿：标题、文案、原创图片、对应模式的文件，以及已核验的飞书记录。文章模式包含可复制的公众号排版，贴图模式包含可直接使用的手机竖版成图。用户说“每生成一篇”包括批量任务中的每一条；候选标题不单独建记录。只整理素材或只分析时，不额外创作内容。

## 执行入口：先询问文章还是贴图

每次启动本skill的创作流程，先检查用户当前请求是否已明确选择文章或贴图；已经明确选择时视为已回答，直接按该模式执行。尚未选择时必须先询问：“这次要做文章，还是贴图？”可用简短双选项：文章（300字内正文＋横版封面＋公众号排版）；贴图（手机竖版成图＋短句情感文案）。等待用户回答后再进入创作，不默认文章，不沿用上一次模式，不在等待期间先生成文案、图片或写入飞书。同一次流程已得到回答，后续续跑不重复询问。用户仅要求修改skill规则时，不启动创作或提出模式问题。

- **文章**：按下文现有文章规则执行，正文≤300字，2.35:1横版封面，公众号HTML排版。
- **贴图**：按“贴图模式”执行；该节覆盖文章模式的篇幅、画幅和HTML交付要求，其余原创性、情感表达、人物服饰、隐去正脸和飞书核验规则照常适用。

## 输入与默认约定

- 使用用户指定的作者、素材表或链接；会话中作者已明确时直接继续。多个作者无法区分时，只询问素材来源，不能随意混合作者。
- 先读飞书现有素材，已有正文和封面不重复抓取。若只有打不开的微信链接，使用可用的公开读取渠道；遇验证或权限阻断时如实说明缺什么，不能用猜测代替原文。
- 默认一次生成一篇。未指定选题时，根据素材的情绪与读者范围自拟新题材，不改写某篇原文来冒充原创。
- 用户已指定此工作流时，向其指定的飞书表写入属于任务范围；不重复索要例行确认。不得自动发布公众号、群发消息或调整分享权限。
- 默认沿用 Claude 暖白排版，不必每次询问；用户本轮指定的风格优先。

## 读取和整理素材

使用 `lark-base` 技能和 `lark-cli`，读其必要命令参考。个人素材默认 `--as user`。飞书目标配置方法见 [references/feishu-target.md](references/feishu-target.md)，首次使用时由用户指定。

先读真实字段与记录，检查分页。保留来源记录ID和链接；用 `+record-download-attachment` 下载封面并逐张查看，不能只凭附件名分析。样本少时明确样本数；未知日期、作者、阅读数据留空，不推填。

整理三个维度，并保存简洁的风格分析：

- 标题：读者、切入点、句式、具体性、情绪强度、标题承诺。
- 正文：开头方式、生活细节、叙述人称、段落节奏、转折与收尾。
- 封面：主体、服装、姿势、场景、构图、光线、色彩、画幅和文字。

用户要求整理原表时，可将标题中混入的作者/日期和正文末尾的阅读数移至对应字段或备注，并纠正过时采集状态；先保存原始快照。只清理格式和元数据，不擅自改写原作者正文。不因新增草稿覆盖用户已有文章。

## 创作正文：最多300字

- 建议180–280字，300是上限，不是目标。计数采用正文全部非空白字符，**标点、数字、字母都计入**；标题、摘要、备注和HTML标签不计。以未加HTML的最终正文计数，排版后再次核对文字未增加。
- 每篇只写一个小场景或一个观察、一处情绪变化。用具体动作和物件支撑情绪，少讲抽象道理。段落长短自然，无需固定段数或小标题。
- 原创性同时检查参考原文和近期已生成草稿。写作前读取可获取的近期草稿标题与正文，比较选题、人物关系、核心矛盾、关键物件、叙述结构和结尾；不能只换地点、物件或几个词，就重复“委屈自己—做件小事—学会爱自己”的同一篇。样本不可获取时注明去重范围，不宣称全库去重。保留参考作者的情绪质感，发展独立的情节和观察。
- 语气要有情感温度：允许写出舍不得、失落、想念、委屈、释然或犹豫，让读者明白这件小事为什么牵动叙述者。动作细节与内心感受相互照应，避免全篇只有动作流水账，也不靠悲惨设定、情绪标签或鸡汤制造共鸣。
- 写好后做一次去套话审稿：删除泛泛开场、堆叠形容词、强行升华、金句串联、刻意煽情，以及连续重复的“不是……而是……”“真正的……”“成年人最好的……”等结构。保留自然停顿，不靠错别字、病句或随机口头禅制造“真人感”。
- 可参考 `stop-slop` 的去套话方法，但不要机械禁用所有副词或牺牲中文表达。目标是自然、具体、克制；不宣称能通过AI检测，也不承诺“零AI痕迹”。
- 不复用原文独特句子、人物关系和完整情节。第一人称虚构随笔可用，但在飞书备注中注明“原创虚构随笔”，不冒充用户或原作者亲历，不伪造引语、统计和事实。

字数可用 Python 校验：`sum(not c.isspace() for c in body)`；超过300必须删改，不能只标注超限后入库。

### 结尾必须完成情绪收束

先写完整的情绪走向，再压缩到300字以内。为结尾留出一至两句的空间，超字数时优先删重复铺垫和无关细节，不能截掉收束句。也不必凑满300字。

结尾应回应开头的困惑、关系或内心阻力，让读者感到叙述者的心境发生了什么变化，或为何仍有一份明确的未尽情绪。可以是贴合场景的心里话、态度、愿望或对细节的新理解；不必强行释怀、总结道理，也不要每篇套用同一种升华句。

动作可以收尾，但前文必须已把它的情感意义写充分。不能把“关灯了”“走回家”“给花换了水”之类的末尾动作自动当成有余味。复读最后两段：如果读者仍会问“然后呢，这件事对你意味着什么”，就补足连接与感受，再重新计数。

结尾反例：“吃完饭，我给它换了水。”在那篇买花文章里，单独停在这里不足以回应开头“只有我，买花没必要”的自我忽视。可沿着“仍有点心疼花钱，但终于承认自己也想每天看到它”的方向收束，具体措辞随本篇重写。只借鉴收束原则，不把示例变成固定句式。

## 标题

可调用相邻的 `zgh-baokuan-title-generator/SKILL.md`，使用前阅读其完整工作流。用户显式指定时必须使用。它主要基于科技类标题：此处借用内容简报、候选对比和兑现度审查，不把科技品牌、实时新闻词和极值词强塞进生活随笔，不把其样本统计当作情感领域定律。

依正文内容选择合适方法，产生候选并选一个最终标题。无需用户逐个确认；候选、分数与取舍可保存为工作文件或备注，飞书标题字段只填最终标题。不要为了“爆款”添加正文没有的矛盾、事实、经历或收益，不能保证阅读量。

## 封面：裙装、背影、日常感

使用 `imagegen` 技能及内置 `image_gen` 生成原创图片。优先参考实际看过的封面在构图、光线和气氛上的共同特点，并应用用户以下偏好：

- 人物明确为成年人，默认约25–35岁女性；不露正脸，选背影或完全遮住面部的侧背影。
- 服饰优先长裙、修身包臀裙或短裙，也可按场景选择其他服饰。不论哪种服饰，都尽量通过合身剪裁、腰线、垂坠感及姿态自然修饰身材：长裙/包臀裙适当呈现腰臀曲线，短裙结合站姿、步态和构图修饰腿型；其他服饰同样注重身形线条，不以宽松遮蔽作为默认方案。保持真实身体比例，不机械复用同一套衣服。
- 姿势、场景、拍摄角度自主设计，与文章情绪相配；可以坐、走、倚靠或站立，避免每次同一个阳台与同一种姿态。自然身体比例，不做夸张修身，不使用走光式视角。
- 默认2.35:1无字横幅，主体保留裁剪余量；真实生活摄影、环境可辨、无水印。不复刻参考图身份或整张画面。

先写本篇封面提示词再生成，明确本篇服饰如何修饰身形及选用的动作与角度。检查服饰与线条表现、正脸隐藏、手脚形态、比例和画幅；不满足要求时有针对性修改。生成失败时保存可继续的草稿并明确封面缺失，不能把提示词或图片URL当作已上传封面。

## 排版与文件

调用相邻 `zgh-space-wechat-layout/SKILL.md`，默认Claude暖白、16px正文、约1.9行高、短段落留白。300字短文不需要复杂卡片或密集标题。排版只调整视觉，不能为凑结构扩写正文。

每篇使用独立目录，保存 `article.md`、`article.html`、`index.html`、`cover.png`、`style-analysis.md`、`cover-prompt.txt` 和含上述文件的 `draft-package.zip`。预览提供“复制HTML”按钮，复制内容仅为公众号正文；标题与封面分别设置。生成图片复制到该目录，避免只依赖生成缓存路径。

验证预览可访问，HTML正文与定稿一致，非空白字符≤300。浏览器可用时查看视觉效果；不可用时说明只完成文件和服务检查，不声称已实测剪贴板。

## 贴图模式：手机竖版与情感钩子

- 默认生成9:16手机竖版成图，适配1080×1920展示；用户指定平台尺寸时以指定值为准。直接为竖构图生成，不能把横图拉伸成长图，也不能粗暴裁掉人物头部、裙摆或关键动作。裙装修饰身形、成年女性、不露正脸等规则保留，姿态与场景自主设计。
- 文案默认20–60字，建议不超过80字（非空白字符含标点），2–4行短句。先用具体处境、真实感受或适度反差制造钩子，再给一句情绪回应；要让读者很快读懂并产生共鸣。不靠虚假悬念、空泛励志、刻意焦虑或夸张承诺吸引点击。
- 短不等于截断：结尾仍须回应开头，可以有余味，但不能只剩半句话、突兀动作或未兑现的悬念。避免每张都用“你不是……只是……”及同一种情绪转折；与近期成稿比较题材和表达，保持原创。
- 贴图默认且必须交付无字图片：不把标题、文案、标点、签名或水印排入图中。文案独立保存在copy.txt及飞书内容字段，标题放标题字段。竖图按照纯摄影构图，不为文字刻意空出大块区域。只有用户在当次明确要求图上加字时才覆盖此默认。生成后检查图片无文字、人物完整及裁切合理。
- 保存 `copy.txt`（独立配文，不上图）、`cover.png`（最终竖版成图）、`style-analysis.md`、`cover-prompt.txt` 和包含这些文件的 `draft-package.zip`；无字竖图就是最终成图，不额外制作加字版。贴图不强制生成公众号HTML，也不把文章模式的横版预览壳作为交付。
- 飞书标题填本条标题，内容填完整短文案，封面附件上传最终竖图，排版文件上传成图包和分析，备注写“模式：贴图；画幅：9:16；文案字数：N”。排版HTML留空；文章模式备注写“模式：文章”。优先复用现有字段，不为了模式新增Base或表。

## 每篇必须写入飞书

1. 核验目标表和字段后追加一条草稿，填入标题、内容、摘要、状态、参考账号、风格分析、排版HTML、封面提示词和备注。备注记录样本范围、正文字数及虚构声明（适用时）。
2. 使用 `+record-upload-attachment` 将实际图片传入附件类型的“封面”；将排版包和风格分析传入“排版文件”。不能只写本地路径或远程URL。
3. 保存创建返回的record_id，后续附件上传与修复使用同一记录。网络结果不明确时先查询是否成功，不盲目重复创建。写入与附件上传串行执行；多篇任务逐篇完成。
4. 回读记录，逐项核验文案、标题及附件名称/数量；文章模式另核验HTML，贴图模式另核验竖版画幅、图片无字以及独立配文。完整后标记“待审阅”；缺文案/图片/本模式所需附件时标记具体待补状态，不能报告完成。
5. 若权限或连接导致入库失败，保留本地完整产物与失败步骤，明确说明尚未入库以及恢复所需操作；不要创建另一个空间兜底，不设置未获授权的定时重试。

最终回复以飞书草稿链接为主，附本次模式、标题、文案字数、对应预览或下载入口和必要限制。贴图展示最终竖版成图；文章提供排版预览。风格分析保存在记录中，不必每次输出长篇拆解。
